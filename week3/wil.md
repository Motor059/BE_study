# 3주차 WIL: JPA와 레포지토리

---

## **레포지토리 계층과 데이터베이스**
- **레포지토리 계층 (Repository Layer)**: 데이터베이스에 접근하여 데이터 생성, 조회, 수정, 삭제 등의 CRUD 작업을 수행하는 계층
- **데이터베이스 연동**: 애플리케이션 서버는 데이터베이스가 이해할 수 있는 SQL을 연결된 커넥션을 통해 데이터베이스에 전달하여 작업을 수행함

## **ORM과 JPA**
- **ORM (Object-Relational Mapping)**: 객체와 관계형 데이터베이스의 데이터를 자동으로 매핑해주는 기술
- **ORM의 장점**: 객체와 데이터베이스 간의 패러다임 차이를 해결하고, 반복적인 CRUD SQL을 자동으로 처리해주어 개발자의 생산성을 크게 향상시킴
- **JPA (Java Persistence API)**: 자바 진영의 ORM 기술 표준으로, 자바에서 객체를 데이터베이스에 저장하고 관리하기 위한 인터페이스와 기능을 제공함

## **엔티티 매니저와 영속성 컨텍스트**
- **엔티티 매니저 (EntityManager)**: 엔티티 객체를 데이터베이스와 연결해주는 창구 역할을 하며, 이를 통해 SQL을 직접 작성하지 않고도 엔티티의 등록(`em.persist()`), 조회(`em.find()`), 삭제(`em.remove()`)가 가능함
- **영속성 컨텍스트**: JPA에서 엔티티를 안전하게 관리하기 위해 내부에 만들어둔 가상 공간
- **엔티티 생명 주기**:
  - **비영속**: 영속성 컨텍스트와 관련이 없는 새로운 상태
  - **영속**: 영속성 컨텍스트에 저장되어 JPA의 관리를 받는 상태
  - **준영속**: 영속성 컨텍스트에 저장되었다가 분리된 상태
  - **삭제**: 영속성 컨텍스트에 삭제될 예정이라고 기록된 상태

## **트랜잭션과 영속성 컨텍스트의 핵심 특징**
- **트랜잭션**: 데이터베이스에서 수행되는 논리적인 작업의 단위로 모든 연산이 성공하면 커밋하여 반영하고, 하나라도 에러가 발생하면 롤백하여 이전 상태로 되돌림
- **1차 캐시**: 한 번 조회한 객체를 영속성 컨텍스트 내부에 저장해두고, 이후 조회 시 데이터베이스를 거치지 않고 재사용하여 성능을 높임
- **동일성 보장**: 트랜잭션 안에서는 같은 엔티티를 여러 번 조회해도 항상 보관된 같은 객체를 반환하므로 동일성이 보장됨
- **트랜잭션을 지원하는 쓰기 지연**: 변경 사항(쿼리)을 즉시 전송하지 않고 모아두었다가 트랜잭션이 커밋되는 시점에 묶어서 한 번에 데이터베이스에 전달하여 네트워킹 최적화를 이룸
- **변경 감지 (Dirty Checking)**: 영속성 컨텍스트가 관리하는 엔티티의 수정 사항을 자동으로 감지하고, 커밋 시점에 맞추어 자동으로 UPDATE 쿼리를 실행함
