# 1주차 WIL: 백엔드 기초와 API 설계

---

## **웹과 네트워크의 이해**
- **인터넷과 웹**: 인터넷은 전 세계의 컴퓨터를 연결하는 네트워크이며, 웹은 그 위에서 정보를 공유하는 서비스
- **클라이언트와 서버**: 클라이언트는 요청을 보내는 주체이며, 서버는 그 요청을 받아 처리한 후 결과를 응답으로 반환
- **URL 구조**: 웹 리소스의 위치를 나타내며 Scheme(프로토콜), Host(IP/도메인), Port, Path, Query 파라미터 등으로 구성

## **HTTP 프로토콜의 특징**
- **기본 개념**: 웹에서 데이터를 주고받기 위한 서버-클라이언트 모델의 프로토콜
- **무상태성(Stateless)**: 서버가 이전의 요청을 저장하지 않고 각 요청을 독립적으로 처리
- **비연결성(Connectionless)**: 요청과 응답이 완료되면 서버와의 연결을 유지하지 않아 자원을 효율적으로 사용
- **HTTP 요청 구성**
    - **메서드**: GET(조회), POST(등록), PUT(전체 교체), PATCH(일부 수정), DELETE(삭제) 등이 있음
    - **상태 코드**: 200(성공), 201(생성 성공), 400(잘못된 요청), 404(찾을 수 없음), 500(서버 오류) 등으로 처리 결과를 나타냄

## **프론트엔드와 백엔드의 협업**
- **역할 분담**: 프론트엔드는 사용자가 보는 인터페이스를 개발하고, 백엔드는 데이터 처리 및 저장(DB 관리)을 담당
- **API (Application Programming Interface)**: 프로그램 간에 기능을 사용할 수 있도록 미리 정해놓은 약속
- **REST API**: HTTP의 장점을 최대한 활용하는 아키텍처 스타일로, 자원은 URL로, 행위는 HTTP Method로 표현

## **Spring Boot**
- **Spring**: 애플리케이션 개발의 효율성을 높여주는 프레임워크로, 기본적인 뼈대를 제공
- **Spring Boot**: 복잡한 초기 설정 과정 없이도 스프링 프레임워크를 빠르고 쉽게 시작할 수 있게 해줌

## **1주차 과제: 온라인 쇼핑몰 API 명세서**

### **상품 관련 기능**
| 기능 | HTTP Method | URI |
| :--- | :--- | :--- |
| 상품 정보 등록 | `POST` | `/products` |
| 상품 목록 조회 | `GET` | `/products` |
| 개별 상품 상세 조회 | `GET` | `/products/{productId}` |
| 상품 정보 수정 | `PATCH` | `/products/{productId}` |
| 상품 삭제 | `DELETE` | `/products/{productId}` |

### **주문 관련 기능**
| 기능 | HTTP Method | URI |
| :--- | :--- | :--- |
| 주문 정보 생성 | `POST` | `/orders` |
| 주문 목록 조회 | `GET` | `/orders` |
| 개별 주문 상세 조회 | `GET` | `/orders/{orderId}` |
| 주문 취소 | `DELETE` | `/orders/{orderId}` |
